# Support

## Usage questions and bugs

Use GitHub Issues for reproducible bugs, portability problems, documentation gaps, and feature proposals that are safe to discuss publicly.

Before filing an issue, include:

- the exact Agent Action Surety commit or package version;
- Node.js or Python version and operating system;
- the smallest reproducible policy/action input that does not contain secrets;
- expected and observed allow/deny behavior; and
- relevant receipt reason codes or sanitized logs.

## Security vulnerabilities

Do **not** use a public issue for an undisclosed vulnerability, bypass, credential exposure, or exploit. Follow [SECURITY.md](SECURITY.md) and report privately to `security@nymrel.com` or `contact@nymrel.com`.

## Project questions

Questions about contribution scope, interoperability, or roadmap priorities can use a public issue when no sensitive information is involved. See [CONTRIBUTING.md](CONTRIBUTING.md), [GOVERNANCE.md](GOVERNANCE.md), and [ROADMAP.md](ROADMAP.md) first.

Commercial support or private implementation work is separate from the guarantees of this MIT-licensed repository and does not change the public project's review or release rules.
